# Genuine Apache-only dbt OSS producer evidence

## Scope
Evaluate an actual pinned official dbt OSS v2 distribution using an original auth-free local DuckDB project comparable to the full dbt 2.0.12 fixture. Establish official provenance, license and adapter availability before generation. Exercise parse/build/catalog and the public catalog consumer; retain a small original artifact regression only if meaningful and supported by observations.

## Non-goals
No full/OSS equivalence claim, synthetic producer evidence, runtime replacement, dependency/support policy changes, cloud/live warehouse/credentials/spend, #468 changes, manual release/tag/package publication, or binary redistribution. No guessed producer or adapter availability.

## Acceptance Criteria
1. Identify a real available official OSS release, immutable package/binary provenance and license; prefer 2.0.12 for the existing comparator, otherwise record the version difference explicitly. Use a separate environment.
2. Verify actual adapter availability and run local parse plus build with catalog output if supported. Record successes, failures, schemas, physical table content, and artifact hashes honestly.
3. Compare caller-visible names/types/comments/order and loader ordinals against original inputs through the existing osmosis consumer; check both model/source maps, source isolation, no fallback when metadata exists and unchanged artifact bytes. Do not infer whole-engine parity from a catalog.
4. Preserve small original non-sensitive artifacts with provenance only when useful. If unavailable, record the exact blocker and do not substitute another producer. Product behavior changes require a separate concrete reproduction and parent scope review.
5. Independently review any retained change, pass all normal exact-head CI, fresh-main guard and post-merge verification before claiming integration.
